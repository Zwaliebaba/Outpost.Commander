# Outpost Commander — Budgets

Status: **living** · What the game's time, size and memory are held to: each budget's target and where the target comes from, the latest measurement with its date, place and method, and what is still to be measured

A row gives only the latest measurement of its quantity. Every earlier one is in [the balance log](../GameDesign/Records/BalanceLog.md), and a new measurement is added there, dated, and replaces the row's. Where a plan or a decision names the run that takes a measurement still to come, that run is in the Outstanding table of [the playtest log](../GameDesign/Records/PlaytestLog.md); the last column here names every measurement still to come, whether a run is named for it or not. A figure here was measured unless the row says it was computed.

---

## How the figures are taken

- **`--measure`** writes every frame's CPU work and GPU work, and every server tick's time and its parts, to a log that `Tools/FrameTimes.py` summarizes as a mean, a median, a 95th and a 99th percentile and the worst, leaving out the first 120 frames.
  - A frame's CPU work runs from the moment the swap chain lets the frame start to the return from `Present`: window messages, the client's update and the recording. Its GPU work is the time between two timestamps at the start and the end of its command list, read back after the frame's fence. The compositor, scanout and the display are not in either.
  - A frame's figures name the display's refresh rate. With vsync on, a frame presents at a whole number of refresh intervals whatever its work ([ADR-006](ADR/ADR-006-renderer-shape.md) decision 3), so the work, not the present interval, is what is held to the budget.
  - A tick's time is the server's own clock round applying its commands, the simulation's step and every snapshot (`Server::TakeTickDurations`), and the hosted players' part after it ([ADR-079](ADR/ADR-079-seat-controller-and-deputy.md) decision 2).
  - The figures come from a Release build. Release has no PIX markers ([ADR-005](ADR/ADR-005-pix-markers.md)), so a Debug capture is where the time is broken into regions, and Release's own timings are what is recorded.
- **The loads.** `--stress` keeps 200 ships and 40 structures in combat (`StressLoad`): each player keeps 100 ships of its starting designs and 20 structures, its Command Station among them, both fleets attack-move on each other's rally, and a lost ship comes back. `--load` places the same count (`PlaceMeasurementLoad`) and orders both players' ships across the map every 200 ticks (`LoadDriver`). `--ai-matches` plays seeded matches between two AIs on the real server ([ADR-038](ADR/ADR-038-phase-one-match-log.md), [ADR-063](ADR/ADR-063-self-play-probe.md)), and `--world-run` a world with an AI in every seat, killed and recovered at random ticks ([ADR-082](ADR/ADR-082-world-log-and-world-run.md)). The tests that measure, `WorldFolderTests.MeasuresALateSave` and `InProcessServerTests.MeasuresTheHostedPlayersTicks`, run only with `OUTPOST_WORLD_MEASURE` set.
- **Order to response.** A script injects right-clicks on ships at rest, spread by a random pause of 150 to 400 ms. The time runs from the script's `QueryPerformanceCounter` reading just before it injects the click, so the input queue's time is in it, to the return from `Present` for the first frame in which an ordered ship's center or nose has moved a pixel at the default view. Scanout and the display's latency are not in it.
- **Where.** The development machine is a laptop with a Qualcomm Snapdragon X X1P64100 (10 cores, 3.4 GHz), 16 GB of memory and its integrated Adreno X1-85, on a built-in 2880×1920 panel at 60 Hz, running Windows 11 Home build 26200 and the Release|ARM64 build (owner, 2026-10-01; [ADR-003](ADR/ADR-003-x64-and-arm64.md)). The Linux container builds the server, the AI and the tests with clang 18 or g++ 13 against stand-ins for the Windows headers; its times are not the development machine's, and a match plays differently on another build, since floats replay only on the binary that played them ([ADR-009](ADR/ADR-009-deterministic-core.md)).
