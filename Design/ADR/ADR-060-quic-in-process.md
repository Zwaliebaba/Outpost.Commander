# ADR-060 — The match's players reach the in-process server over QUIC

Status: **accepted** · 2026-10-04

## Context

ADR-004 chose QUIC through MsQuic for the network transport and wrote no QUIC code until the server left the process. On 2026-10-04 the owner asked for the client–server traffic to go over QUIC now, with the server still inside the client, so the transport is built and exercised before it has to cross a network. The owner decided four things that day: QUIC carries the shell's matches, and the headless runs keep the loopback; the package's minimum rises to Windows 11; the server makes a self-signed certificate of its own, which the client pins; and snapshots travel on one reliable stream.

ADR-004 expected snapshots to go as unreliable datagrams, with only the newest one mattering. Today's snapshot does not allow that. It carries the shots and destructions of its one tick, so a lost snapshot loses an explosion or a Mining Rig's alert, and it carries the player's whole catalogue of components and research every tick. Encoded as below, player 1's snapshot is 8,065 bytes at the start of a match (49 entities) and 18,785 bytes under task 2.7's measurement load (173 entities in its fogged view). Those figures were measured on 2026-10-04 by encoding the 20th tick's snapshot from the repository's tuning and map, built with g++ 13 on Linux. A QUIC datagram is about 1,200 bytes.

## Decision

1. **The shell's matches go over QUIC.** The server is made with `ServerDesc::quic`. It then listens on `127.0.0.1` with a port the system chooses, and the shell opens a seat for each player with `Server::OpenSeat`. Each player, the human and the AI, connects with a `QuicTransport` and takes its seat before the shell starts the server. The measurement runs (`--measure`, `--load`, `--stress`) are matches too, so they go over QUIC as well. The AI-against-AI matches (`--ai-matches`) and every test that steps the server keep `Server::Connect`'s loopback: a stepped server cannot wait for a network, and ADR-038's headless runs depend on it not having to.
2. **One connection per player, with one bidirectional stream that the client opens.** Commands go up it and snapshots come down it, reliably and in order, which is what `Transport::Receive`'s "oldest first" promises. The listener lets a client open one stream and no more. Each message on the stream is its length in four bytes, little-endian, and then the message. A length over 64 MiB is a broken stream, and the channel closes the connection with `Neuron::FRAMING_ERROR_CODE`.
3. **The engine moves bytes and the game gives them meaning (R9).** `NeuronCore`'s `QuicChannel` and `QuicListener` carry messages and know nothing of commands or snapshots. `msquic.h` is included only by `QuicChannel.cpp` (ADR-004). `GameProtocol`'s `WireFormat` encodes the messages, `QuicTransport` is the client's end, and `InProcessServer` is the server's end.
4. **The wire format is written by hand, field by field, in declaration order.** A message starts with its kind, which is its index in `Message`: hello, welcome, command or snapshot. Integers are little-endian in their own width, and floats and doubles cross as their bits. A string or a vector starts with a 32-bit count, an optional starts with a flag byte, and a variant starts with its alternative's index. Each type's fields are listed once, by a structured binding in `WireFields.h`, and both directions read that list; `ByteFormat.h`'s `ByteWriter` and `ByteReader` write and read them, and a world's save is written by them too ([ADR-077](ADR-077-world-state-on-disk.md)). A field added to a type and not to the list does not compile. The decoder refuses anything the encoder could not have written: a message cut short or running on, a flag that is not 0 or 1, an enumerator past the last, a variant index past the last alternative, and a count larger than the bytes left. It adds a vector's elements as it reads them, so a lying count runs out of bytes before it runs out of memory. An enumerator added to the end of an enumeration has to be added to its `LastOf` in `WireFields.h`, or messages carrying it are refused.
5. **A client takes a seat with a hello, and the server answers with a welcome.** The hello carries `PROTOCOL_VERSION`, the player and the seat's token. The server seats the client only if it opened that seat and the token is the seat's; a match's seat only before it starts, and a world's at any time, the newest connection holding it ([ADR-078](ADR-078-dedicated-server.md)). It then sends a welcome, and from there it takes every message as a command for that seat. The player a command carries is still set from the seat, never from the client (ADR-002). Anything else closes the connection, with a `CloseReason` as its QUIC error code: `WrongVersion`, which a hello's first field says before it is decoded, `SeatRefused` or `MalformedMessage`; and `SeatTaken` for a connection whose seat a newer one took. A match's `Start` throws while a seat is still open.
6. **The server makes its own certificate, and the client pins it.** The listener makes a self-signed certificate for `CN=localhost`, valid for a year. It uses an RSA-2048 key that CNG persists in the user's key store, under `Neuron.QuicListener.` and a GUID, and deletes when the listener goes. A world's listener keeps its certificate and key instead ([ADR-078](ADR-078-dedicated-server.md)). Schannel cannot use a key that exists only in the process, so the key has to be persisted. `OpenSeat` returns the address, the port and the SHA-256 of the certificate's DER encoding. The client turns MsQuic's own validation off and accepts only a certificate with that hash. The dedicated server publishes its hash the same way, in its join files (ADR-078). Pinning is how a client knows a server that no public authority vouches for.
7. **MsQuic's threads run the server's end.** A command is decoded on the connection's MsQuic thread and queued in the seat's `LoopbackChannel`, under the lock it already has (ADR-025). The tick takes it from there, so a QUIC command and a loopback command reach the simulation the same way. The tick encodes each seat's snapshot on the server's thread and hands it to MsQuic. Which channel a seat has is guarded by the server's seat lock, because MsQuic's thread sets it when the hello arrives. The listener is destroyed after the server's thread has stopped and before the connections, so no MsQuic callback outlives what it touches.
8. **The package's minimum is Windows 11, `10.0.22000`.** QUIC needs TLS 1.3, which Schannel has from Windows 11 and Windows Server 2022 (ADR-004). Every match now uses QUIC, so Windows 10 could not play one.

## Consequences

- **A snapshot is encoded and decoded once per player per tick.** On the Linux container, encoding and decoding the snapshot under the measurement load took 76 µs together, averaged over 200 runs. That figure is from g++ 13 with the libraries built `-O1`, not MSVC Release. Encoding runs inside the tick's `Snapshots` part, so the tick timings of design §3 now include it. Decoding runs on the frame loop in `QuicTransport::Receive`. Neither has been measured under MSVC.
- **Starting a match makes a key and a certificate, and two handshakes.** The listener is made with the server, so the RSA key is generated while the menu shows: in the background at startup (ADR-049), and on the frame loop when a match ends and the next server is made. The handshakes happen when the match starts. None of these has been timed on the development machine.
- **What the AI and the human see is unchanged.** Snapshots arrive whole and in order, as they did through the loopback. Commands are applied at the start of the first tick after they arrive, as before.
- **A connection that drops is not recovered by the client.** Its next `Receive` throws, saying why, in the server's words when the server closed it, and the shell goes back to the menu with the reason ([ADR-078](ADR-078-dedicated-server.md)). The server drops snapshots for a seat whose connection has gone. A world's seat is taken again by the player's next connection.
- **What was tested, and where.** `WireFormatTests` round-trips every order, and a snapshot with every field set, to the same bytes. It also checks that every truncation of that snapshot is refused, as are a byte appended and each kind of value no field can take. `QuicTransportTests` plays the server over real QUIC: snapshots for every tick arrive in order, an order reaches the simulation, and the client learns that the server has gone. It also refuses a taken seat, an unopened seat and a certificate with another hash, and it does not start with a seat open. On 2026-10-04 both suites and `InProcessServerTests` ran on Linux against MsQuic 2.6.1's OpenSSL build, with an OpenSSL certificate standing in for the CNG one. They ran three times in a row with no failure, and `QuicTransportTests` and `InProcessServerTests` ran once more under ThreadSanitizer. The one ThreadSanitizer report lay between two of MsQuic's own threads, inside the library. With the client's pinning disabled, the certificate test fails. The Schannel path, the CNG certificate and the MSVC build are checked by CI's Debug|x64 test run, and only there.
- **A match's listener binds `127.0.0.1` only,** so it is not reachable from another machine. Whether Windows Defender Firewall still asks about it the first time a packaged build listens has not been checked. The dedicated server binds the address its world's settings give (ADR-078).

## What this forecloses

- **Unreliable datagrams for snapshots,** until the snapshot is split into state that may be dropped and events that may not, or is sent as deltas. That would be a new protocol version and an amendment to this ADR.
- **Validating the server's certificate against a root** in place of pinning, without changing this ADR.
- **QUIC in the headless runs and the tests that step the server.** They keep the loopback, which stays a `Transport` of its own.
- **Windows 10.** A fallback to the loopback there would be a second live path that nothing exercises.
