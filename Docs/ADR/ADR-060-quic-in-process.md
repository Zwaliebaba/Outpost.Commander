# ADR-060 — The match's players reach the in-process server over QUIC

Status: **accepted** · 2026-10-10
Owns: in-process-quic, wire-format, message-framing, seat-hello, certificate-pinning, protocol-version

## Context

The network transport is QUIC, through MsQuic ([ADR-004](ADR-004-quic-transport.md)). A match's server runs inside the game's process, and its players reach it over QUIC all the same (owner, 2026-10-04), so the transport is built and exercised in every match before it has to cross a network to a universe's dedicated server ([ADR-078](ADR-078-dedicated-server.md)).

A snapshot carries the shots and destructions of its one tick, so a lost snapshot loses an explosion or a Mining Rig's alert. It carries the player's whole catalogue of components and research every tick. It is many times the size of a QUIC datagram, which is about 1,200 bytes.

The game's servers, a match's in its process and a universe's on a player's machine, have no name that a public authority vouches for, and QUIC needs TLS 1.3, which Schannel has only from Windows 11 and Windows Server 2022.

## Decision

1. **The shell's matches go over QUIC** (owner, 2026-10-04). The server is made with `ServerDesc::quic`. It then listens on `127.0.0.1` with a port the system chooses, and the shell opens a seat for each player with `Server::OpenSeat`. Each player, the human and the AI, connects with a `QuicTransport` and takes its seat before the shell starts the server. The measurement runs (`--measure`, `--load`, `--stress`) are matches too, so they go over QUIC as well. The AI-against-AI matches (`--ai-matches`) and every test that steps the server keep `Server::Connect`'s loopback: a stepped server cannot wait for a network, and ADR-038's headless runs depend on it not having to.
2. **One connection per player, with one bidirectional stream that the client opens** (owner, 2026-10-04). Commands go up it and snapshots come down it, reliably and in order, which is what `Transport::Receive`'s "oldest first" promises. The listener lets a client open one stream and no more. Each message on the stream is its length in four bytes, little-endian, and then the message. A length over 64 MiB is a broken stream, and the channel closes the connection with `Neuron::FRAMING_ERROR_CODE`.
3. **The engine moves bytes and the game gives them meaning (R9).** `NeuronCore`'s `QuicChannel` and `QuicListener` carry messages and know nothing of commands or snapshots. `msquic.h` is included only by `QuicChannel.cpp` (ADR-004 decision 4). `GameProtocol`'s `WireFormat` encodes the messages, `QuicTransport` is the client's end, and `InProcessServer` is the server's end.
4. **The wire format is written by hand, field by field, in declaration order.** A message starts with its kind, which is its index in `Message`: hello, welcome, command or snapshot. Integers are little-endian in their own width, and floats and doubles cross as their bits. A string or a vector starts with a 32-bit count, an optional starts with a flag byte, and a variant starts with its alternative's index; a `std::pair` and a `std::array` are their elements in order. Each type's fields are listed once, by a structured binding in `WireFields.h`, and both directions read that list; `ByteFormat.h`'s `ByteWriter` and `ByteReader` write and read them, and a universe's save is written and read by them too ([ADR-077](ADR-077-universe-state-on-disk.md) decision 1). A field added to a type and not to the list does not compile. The decoder refuses anything the encoder could not have written: a message cut short or running on, a flag that is not 0 or 1, an enumerator past the last, a variant index past the last alternative, and a count larger than the bytes left. Its refusal names what it is reading, "A message from the network" or "A saved universe". It adds a vector's elements as it reads them, so a lying count runs out of bytes before it runs out of memory. An enumerator added to the end of an enumeration has to be added to its `LastOf` in `WireFields.h`, or messages carrying it are refused.
5. **A client takes a seat with a hello, and the server answers with a welcome.** The hello carries `PROTOCOL_VERSION`, `WireLayoutHash`, the player and the seat's token. `PROTOCOL_VERSION` stays 1 until the game is live (owner, 2026-10-09), so it is the layout's hash that tells a client of another build: the 64-bit FNV-1a of `WireLayout`, which describes every message as `ByteLayout` describes a save ([ADR-077](ADR-077-universe-state-on-disk.md) decision 6), so that a field added, taken away, reordered or given another type anywhere in a message changes it. The version and the hash stay the hello's first two fields, and the server reads both before it decodes the rest (`PeekHelloVersion`, `PeekHelloLayout`), since the rest of another build's hello may not decode. The server seats the client only if it opened that seat, the token is the seat's ([ADR-078](ADR-078-dedicated-server.md) decision 3), and the seat may be taken now ([ADR-078](ADR-078-dedicated-server.md) decision 4). It then sends a welcome, and from there it takes every message as a command for that seat. The player a command carries is still set from the seat, never from the client (ADR-002 decision 2). Anything else closes the connection, with a `CloseReason` as its QUIC error code: `WrongVersion` for a hello of another version or layout, or one cut short before its hash ends, `SeatRefused` or `MalformedMessage`; and `SeatTaken` for a connection whose seat a newer one took (ADR-078 decision 4).
6. **The server makes its own certificate, and the client pins it** (owner, 2026-10-04). The listener makes a self-signed certificate for `CN=localhost`, valid for a year. It uses an RSA-2048 key that CNG persists in the user's key store, under `Neuron.QuicListener.` and a GUID, and deletes when the listener goes. A universe's listener keeps its certificate and key ([ADR-078](ADR-078-dedicated-server.md) decision 7). Schannel cannot use a key that exists only in the process, so the key has to be persisted. `OpenSeat` returns the address, the port and the SHA-256 of the certificate's DER encoding. The client turns MsQuic's own validation off and accepts only a certificate with that hash. The dedicated server publishes its hash the same way, in its join files (ADR-078 decision 8). Pinning is how a client knows a server that no public authority vouches for.
7. **MsQuic's threads run the server's end.** A command is decoded on the connection's MsQuic thread and queued in the seat's `LoopbackChannel`, under the lock it has (ADR-025 decision 4). The tick takes it from there, so a QUIC command and a loopback command reach the simulation the same way. The tick encodes each seat's snapshot on the server's thread and hands it to MsQuic. Which channel a seat has is guarded by the server's seat lock, because MsQuic's thread sets it when the hello arrives. The listener is destroyed after the server's thread has stopped and before the connections, so no MsQuic callback outlives what it touches.
8. **The package's minimum is Windows 11, `10.0.22000`** (owner, 2026-10-04). QUIC needs TLS 1.3, which Schannel has from Windows 11 and Windows Server 2022 (ADR-004). Every match uses QUIC, so Windows 10 could not play one.

## Consequences

- **A snapshot is encoded and decoded once per player per tick.** Encoding runs inside the tick's `Snapshots` part, so the tick's timings include it. Decoding runs on the frame loop in `QuicTransport::Receive`. A snapshot's size and what encoding and decoding cost are in `Docs/Budgets.md`.
- **Starting a match makes a key and a certificate, and two handshakes.** The listener is made with the server, so the RSA key is generated while the menu shows: in the background at startup (ADR-049), and on the frame loop when a match ends and the next server is made. The handshakes happen when the match starts.
- **The AI and the human get every snapshot whole and in order.** Commands are applied at the start of the first tick after they arrive.
- **A connection that drops is not recovered by the client.** Its next `Receive` throws, saying why, in the server's words when the server closed it, and the shell goes back to the menu with the reason ([ADR-078](ADR-078-dedicated-server.md) decision 10). The server drops snapshots for a seat whose connection has gone. A universe's seat is taken again by the player's next connection.
- **Tests.** `WireFormatTests` round-trips every order, and a snapshot with every field set, to the same bytes. It also checks that every truncation of that snapshot is refused, as are a byte appended and each kind of value no field can take. `QuicTransportTests` plays the server over real QUIC: snapshots for every tick arrive in order, an order reaches the simulation, and the client learns that the server has gone. It also refuses a taken seat, an unopened seat and a certificate with another hash, and it does not start with a seat open. The Schannel path, the CNG certificate and the MSVC build are checked by CI's Debug|x64 test run, and only there.
- **The hello's checks.** `WireFormatTests.SaysHowItsMessagesAreLaidOut` checks that the hello's version and layout hash are its first two fields, that the hash is of `WireLayout`, and what the two peeks read from a hello, one cut short and a welcome. `QuicTransportTests.RefusesAHelloOfAnotherVersion` and `RefusesAHelloOfAnotherLayout` check that the server closes with `WrongVersion` on a hello of another version, of another layout, or cut short inside its hash, and seats this build's own hello. The QUIC tests run in CI's Debug|x64 run only.
- **A match's listener binds `127.0.0.1` only,** so it is not reachable from another machine. The dedicated server binds the address its universe's settings give ([ADR-078](ADR-078-dedicated-server.md) decision 6).

## What this forecloses

- **Unreliable datagrams for snapshots,** until the snapshot is split into state that may be dropped and events that may not, or is sent as deltas. That would change the wire format and this ADR.
- **Validating the server's certificate against a root** in place of pinning, without changing this ADR.
- **QUIC in the headless runs and the tests that step the server.** They keep the loopback, which stays a `Transport` of its own.
- **Windows 10.** A fallback to the loopback there would be a second live path that nothing exercises.
