# ADR-101 — A universe's overseer has a channel of its own to the server, which tells it the universe and changes nothing

Status: **accepted** · 2026-10-27
Owns: overseer-channel, overseer-messages, overseer-file, overseer-health, universe-view, process-figures

## Context

The overseer is the dedicated server's management console: a separate application that oversees the whole universe, its health, where its players are and how their connections do (owner, 2026-10-27). The owner decided that it sees in full sight, watches and acts on the server but never on the simulation, is drawn with the game's own interface, and reaches the server from the same machine or the LAN. What it shows and the order it is built in are [the overseer's proposal](../Plans/UniverseOverseer.md) and [its plan](../Plans/ImplementationPlan-Overseer.md). This ADR records the channel the server keeps for it, and what crosses it. The server's own measurements it reads are [ADR-082](ADR-082-universe-log-and-universe-run.md)'s; the actions, Save now, Stop, Drop link and New token, are not decided here.

## Decision

1. **The server listens for its overseer on a QUIC listener of its own** (`OverseerLink`, in `GameLogic`), beside the game's: the application protocol `outpost-overseer/1`, so a player's game, which negotiates `outpost-commander/1`, cannot reach it; on the settings' `overseerAddress` and `overseerPort`, `127.0.0.1` and 45001 unless they name others ([ADR-078](ADR-078-dedicated-server.md) decision 2), so nothing reaches it from another machine until the owner opens it; presenting the universe's kept certificate (ADR-078 decision 7), which the overseer pins as a player does. An overseer may send no message longer than `OVERSEER_MESSAGE_LIMIT_BYTES`, 256, before its hello and after: it sends only short ones. `InProcessServer::Oversee` makes the link before the server starts, for a universe's server only.
2. **`Overseer.json` in the universe's folder tells the overseer where the server is** (`OverseerTicket`): the host it reaches the server at, the port, the certificate's SHA-256 and a 128-bit token from `std::random_device`, as a join file holds a seat's (ADR-078 decisions 3 and 8). The server makes the token on its first run and keeps it, reading it back from the file; one it cannot read is made afresh, saying so. It writes the file at each start, so that the host and the port follow the settings: the loopback when it listens there, the settings' host when it listens on every address (`*`, `0.0.0.0` or `::`), and otherwise the address it listens on. Whoever reads the file has the overseer's powers: ADR-078's trust of a circle of friends.
3. **One overseer at a time, the newest connection to show the token.** A hello's version and its layout's hash are read before it decodes, so that a hello of another build is told from a broken one, as the game's is ([ADR-060](ADR-060-quic-in-process.md) decision 5); then its token is compared with the universe's, every byte whatever the first difference. A refusal closes the connection with its reason (`OverseerCloseReason`): `WrongVersion`, `TokenRefused`, or `MalformedMessage` for a first message that is no hello, a message after it that is neither a sight nor a held view, a sight of a seat the universe does not have, and no hello within `HELLO_TIMEOUT`, as the game's listener closes one. A welcomed overseer takes the channel from the one that held it, which is closed with `Taken`.
   - **The welcome is sent on MsQuic's thread,** from what was made once as the link is made and the day's records the link keeps (decision 7), so that an overseer is welcomed while the server's thread is stuck: the game's wire layout, protocol and universe state version, the tick rate, the universe's folder, its seats, each a player's or an AI empire's with its difficulty, its sectors with their shapes and its asteroid fields, which never change, what the server came back from as it started, the save of a tick and the commands replayed of those logged after it, or none for a new universe, and the seconds of ticks between two saves (`UNIVERSE_SAVE_SECONDS`); and the day's records.
   - **No state says the server is recovering** (owner, 2026-10-27). It replays its command log in setup, before its listeners exist, and the log holds at most a minute of commands since the last save (`UNIVERSE_SAVE_SECONDS`), so the overseer finds no server meanwhile, and the welcome says after what it came back from.
4. **The overseer's messages are a set of their own** (`OverseerProtocol.h`, in `GameProtocol`): a variant, `OverseerMessage`, encoded as the game's are, which message it is and then its fields in order (ADR-060 decision 4), with a version of its own, `OVERSEER_PROTOCOL_VERSION`, which stays 1 until the game is live, as the game's does. Its layout is the overseer's messages' followed by the game's, `WireLayout()`, since the universe's view crosses as the game's own state messages (decision 6), and its 64-bit FNV-1a is what the hello carries: a change to either refuses an overseer of another build. The game's messages, and their hash, do not change.
5. **`Health` once a second, from the server's main thread** (`InProcessServer::Report`), while an overseer holds the channel:
   - **What the main thread knows:** the wall time; each tick's time since the last `Health`, in the order they ran, from the tick timings it takes (`TakeTickTimings`, which is still where a failure on the server's thread is thrown again), so that the overseer takes any percentile over any window; each tick part summed over them, and the longest tick's largest part; the ticks dropped after a stall since the last `Health` (ADR-009); and the process's figures (decision 9).
   - **What the server's thread kept** at the last second of ticks, as it samples the seats' connections (ADR-004 decision 6): the tick; each seat's player and who plays it (`SeatPlay`), its link (`SeatLink`: none for an AI empire's, open while no connection has taken it, online, or gone) and the tick it became so, and, while it is gone and its player still plays, the tick its deputy takes it ([ADR-079](ADR-079-seat-controller-and-deputy.md) decision 4); its connection's figures; the commands applied for it and refused it in the second ([ADR-094](ADR-094-a-refused-command-is-told.md)); its Ore, income, fleet against its cap, nodes held and topics researched; while it has lost, the tick it restarts at or has waited since ([ADR-084](ADR-084-universe-without-an-end.md) decision 4); and, while its deputy plays it for a player who has held it, the report the server keeps of what that player misses, which the player is handed on coming back ([ADR-080](ADR-080-events-and-scheduled-orders.md) decision 7; owner, 2026-10-28). With them the battles under way, as the universe log keeps them, the joins since the server started by outcome, and the connections the game's listener holds.
   - **A stuck tick still sends `Health`,** whose tick then stands still, since the two come from two threads ([ADR-025](ADR-025-server-thread.md)): the overseer tells a stalled server from a silent one by it.
6. **The universe's view twice a second** (`OVERSEER_VIEWS_PER_SECOND`), built by the server's thread after every tick of that many, while an overseer holds the channel, and timed as a tick part of its own, `TickPart::Overseer`.
   - **Full sight** (`Simulation::BuildFullSight`): every entity as its owner sees it, every shot and destruction of the tick, every sector with its holder and state, and the map's size, under fog of war or not, and no player's own figures. It changes nothing `Simulation` holds (R18). Or, while `WatchSightMessage` names a seat, a copy of that seat's own snapshot of the tick, which the server built for it already.
   - **It crosses as the game's own state message** (`StateMessage`), without its catalogue and its events, on a stream of its own that a newer view abandons ([ADR-096](ADR-096-events-and-state-cross-apart.md)), whole or as what changed since the newest view the overseer says it holds (`ViewHeldMessage`), as a seat's state does ([ADR-098](ADR-098-a-state-crosses-as-what-changed.md)): the server keeps the views it sent in a `SentStates`, which a newer overseer's taking clears, and the overseer puts them together with `HeldStates`, and with the welcome's sectors and fields (`PutCatalog`).
7. **The universe log crosses as it is written.** Once the link is made, the log keeps each line it writes (`UniverseLog::KeepLines`), and the server's thread sends a tick's lines in one `LogRecordsMessage` at the tick's end. The link keeps the last `OVERSEER_RECORDS_KEPT`, 500, which a welcomed overseer is sent after its welcome: read from the end of `Universe.log` as the link is made (`UniverseLog::ReadLastRecords`), whole lines only, so that they reach back before the server last started. Every message to the overseer's stream is sent under one lock, so the welcome comes first, and the records kept follow it before any newer one.
   - **The day's records cross in the welcome** (owner, 2026-10-28): the records the overseer's lanes of who played and its windows are drawn from, of the last day of universe time (`DAY_RECORDS_SECONDS`), the lanes' `seat`, `start` and `battle`, a seat's `join` and `hour`, and the server's `tick` and `dropped` (`IsDayRecord`), and each seat's last hand-over before the day, which says who played the seat as the day began (`KeepDayRecords`, in `GameProtocol`). A save is not one: the log writes one a minute, and its last records hold hours of them. The link reads them from the whole of `Universe.log` once, as it is made (`UniverseLog::ReadDayRecords`), and keeps them as the log writes them, the day ending at the newest record written, so that an overseer that connects days after the server started is told the day before it. A recovery's `start` drops what the log wrote past the tick the universe came back to, which a universe that did not go on wrote.
8. **`Closing` says how the server ends:** stopped by its owner, by Ctrl+C, Ctrl+Break or closing its window; by Windows, signing out or shutting down, which `ServerConsole` tells apart; or by a failure on the server's thread, with the failure's message; and the tick of the universe's last save, which it comes back from with the commands logged after it. `OutpostServer` sends it before the server goes, and before it reports a failure. The link then waits up to a second for the overseer to have acknowledged all that was sent, since closing a connection drops what it has yet to deliver, and closes it with `Finished`. A failed assertion ends the process at once ([ADR-093](ADR-093-a-failed-assertion-ends-the-process.md)) and sends nothing.
9. **The process's figures come from `Neuron::ProcessMeter`,** in `NeuronServer`, which knows no game concept (R9): the working set and private bytes (`GetProcessMemoryInfo`), the CPU since the last measure in hundredths of a core (`GetProcessTimes`), the threads (a Toolhelp snapshot of the system's processes), the handles (`GetProcessHandleCount`), how long the process has run, and the disk free to it under the universe's folder (`GetDiskFreeSpaceExW`), all in the Windows SDK and `kernel32`, so R14 holds. A figure Windows does not give is zero, not a failure: the meter only reports.

## Consequences

- **The view costs the server's thread** a full-sight snapshot, or a copy of a seat's, and its encoding, twice a second, only while an overseer holds the channel. It is timed as `TickPart::Overseer`, so the tick's timings, the universe log's `tick` records and `Health` include it. It is not yet measured against the tick's budget ([the budgets](../Budgets.md)); the overseer's first run with a universe under load measures it.
- **The overseer is told nothing the server does not already keep,** but the seats' second, which the server's thread now keeps each second whether or not an overseer is connected.
- **`TickPart` has a thirteenth part.** The measurement log names its parts in its own first lines, and the universe log names each by `TickPartName`, so neither reader changes.
- **The universe's settings have two members more,** which settings made before them read as their defaults; nothing a universe saves changes (R18).
- **Tests.**
  - `OverseerProtocolTests`: every message decoded as it was encoded, a hello of another build read before it decodes, the game's layout within the overseer's, and what is no message refused. `OverseerTicketTests`: the file read back as written, and every refusal.
  - `UniverseSettingsTests`: the overseer's address and port, their defaults, their refusals and the overseer's file's host. `UniverseLogTests`: the overseer's records, the lines kept for its stream, the last records read from a log's end, the day's records read from a whole log, and the battles under way. `DayRecordsTests`: a record's kind and tick, the day's kinds, the day and each seat's hand-over before it, and what a recovery went back past. `FogTests.FullSightSeesThroughTheFog`. `InProcessServerTests.KeepsEachSecondForTheOverseersHealth`: each tick's time, the dropped ticks, and each seat's second, from a server stepped by hand.
  - `ProcessMeterTests`: the process's figures, and the CPU of a thread that spins and of one that sleeps.
  - `OverseerLinkTests`, over a real connection: the welcome and the log's last records; each refusal and its record; the newest overseer holding the channel; `Health` once a second, with a seat taken; the view twice a second, a seat's sight and back, and the log's new records; `Closing`, and the welcome of a universe that came back from its save; and a welcome's day's records, those written since the link was made and a join's among them. `QuicTransportTests.TellsTheOverseerWhatAnAwayPlayerMisses`: an away seat's report in `Health`, from the tick its deputy took it. QUIC runs in CI's Windows run only.

## What this forecloses

- **An overseer that changes the simulation.** Nothing it sends reaches a tick; the actions it may take on the server are their own decision.
- **Two overseers at once.** The newest holds the channel.
- **The overseer's port reached from the internet by default.** A token in a file is too weak for a channel that will be able to stop the server; a stronger authentication would be a decision of its own.
- **A state that says the server is recovering,** while setup replays the command log before the listeners exist.
- **The game's messages carrying anything for the overseer.** Its messages are its own, and only their layout's hash ties the two.
