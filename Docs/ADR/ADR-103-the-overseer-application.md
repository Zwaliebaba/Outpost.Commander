# ADR-103 — The overseer is a windowed executable of its own, drawn on the canvas, whose model and link are GameApp's

Status: **accepted** · 2026-10-28
Owns: overseer-application, overseer-link, overseer-model, overseer-overview

## Context

The overseer is the dedicated server's management console (owner, 2026-10-27): it watches a universe over a channel of its own, which [ADR-101](ADR-101-the-overseers-channel.md) owns, and never changes the simulation. What it shows and the order it is built in are [the overseer's proposal](../Plans/UniverseOverseer.md) and [its plan](../Plans/ImplementationPlan-Overseer.md). The owner decided that it is native and drawn with the game's own interface, a project of its own with its model and layout in `GameApp` (owner, 2026-10-27), not packaged (owner, 2026-10-28), and always run from a machine with a GPU (owner, 2026-10-28). This ADR records the application: its project, how it finds its universe, its window, its end of the channel, what it keeps of what the server says, and how its overview is built.

## Decision

1. **`OutpostOverseer` is a Win32 executable** (`SubSystem` Windows), not packaged, with ADR-002's row: it includes and links `NeuronCore`, `NeuronClient`, `GameProtocol` and `GameApp`, and neither `GameLogic`, `NeuronServer` nor `Opponent`. Its shell, `WinMain.cpp`, is all it holds: its model, its link and its overview are `GameApp`'s, so that `GameAppTests` drives them without a window or a GPU. It ships the game's `Models.json` beside it in `Assets`, for the seats' colors (decision 7). Neither the game nor the server includes it.
2. **It oversees the universe whose `Overseer.json` it is given** (ADR-101 decision 2): its argument, the file or the folder that holds it, or with none the default universe's folder in the owner's documents, where `OutpostServer` runs it with none ([ADR-078](ADR-078-dedicated-server.md) decision 1). With no file there it says where it looked, that the server writes the file each time it runs, and ends.
3. **Its window opens windowed, and Alt+Enter toggles full screen,** as the game's does ([ADR-006](ADR-006-renderer-shape.md) decision 1): a resizable window of a 1600×900 client area, centered on the primary monitor. `Neuron::Window` takes where it starts and whether it holds the cursor while full screen (`Window::Desc`); the overseer holds it never, since it has no edge scroll ([ADR-012](ADR-012-rts-camera.md)).
4. **It draws on the hardware adapter only** (owner, 2026-10-28): its renderer is the game's (ADR-006 decision 6), which skips software adapters. On a machine with none it says so and where to run it instead, a PC on the server's network with the universe's `Overseer.json`, and ends.
5. **Its end of the channel is `OverseerClient`.** It connects on a thread of its own, so that the frame loop goes on drawing, to the file's host and port with the application protocol `outpost-overseer/1`, pinning the file's certificate (ADR-101 decision 1). Connected, it says hello with the file's token and then the sight it watches, if the owner picked one (`WatchSightMessage`); it hands what arrives to its model, the overseer's own stream first so that a welcome is in before the views put together with it, and tells the server the tick of each view it now holds (`ViewHeldMessage`) and each action the owner asks for (`OverseerClient::Act`, [ADR-104](ADR-104-the-overseers-actions.md)). It reads the connection's round trip once a second. A connection that goes, or that cannot be made, gives its model the server's reason when its close names one (`DescribeOverseerClose`), and otherwise the connection's own words, and the next is tried every `REJOIN_INTERVAL`, 2 s, each given that long to be made, as the game gives a lost universe's joins (ADR-078 decision 10), so that closing the overseer waits no longer for one.
6. **What it knows is `OverseerModel`'s,** which holds no connection, so that a test hands it messages as bytes: the welcome; the newest `Health` and the last hour of them, `HEALTH_KEPT`, each with when the overseer heard it on its own clock; the last `RECORDS_KEPT`, 10,000, of the log's records; the day's records, which who played and the windows are drawn from, the welcome's and every one the stream brings, for the day of universe time that ends at the newest tick it was told of, by `KeepDayRecords` as the server keeps them ([ADR-101](ADR-101-the-overseers-channel.md) decision 7), and none twice: the log's last records, which the server sends again after the welcome, give day's records the welcome gave already and older ones the day dropped, among them a start that would go back past the day's records, so a day's record the stream brings is taken only when it is of the day and not yet kept; the newest view, put together with the views held (`HeldStates`, [ADR-098](ADR-098-a-state-crosses-as-what-changed.md)) and with the welcome's sectors and fields (`PutCatalog`); what came of the latest action it asked for and when it heard it (`ActionResultMessage`, ADR-104 decision 5); how the server ended, once it has said (`ClosingMessage`); and why the last connection went and when. A welcome starts a connection's knowledge: the views held go, since the server sends a new connection whole views first, the records go, since it sends its last ones again, and the latest action's result goes. A view that crosses before its connection's welcome is not taken. What the model knew stays while no connection brings more.
7. **The overview is `OverseerScreen`,** built on the canvas ([ADR-100](ADR-100-the-canvas.md)) in the game's look, the theme `Hud::Theme` with its typefaces and sprites, and laid out on ADR-006 decision 5's 1920×1080 reference frame, scaled to the window as the HUD is, with no scale of its own ([ADR-070](ADR-070-interface-scale.md) is the game's). It keeps what its widgets share and what the owner picked on it, and no GPU state: the shell draws its display list through the UI pipeline. From the top:
   - **The header:** the universe's folder, its server, and the build it runs, the game's wire layout, protocol and universe state version; the server's state, as the overseer tells it from `Health` and `Closing` (ADR-101 decisions 5 and 8): Running while `Health` comes and its tick moves, with how long the process has run, the overseer's round trip and what the server came back from; Stalled while `Health` comes and its tick has stood for `STALLED_AFTER`, 2 s, from the first `Health` heard at that tick to the latest, which a stuck server's thread does while its main thread still reports ([ADR-025](ADR-025-server-thread.md)), with the tick and how long it has stood; No word once no `Health` has come for `NO_WORD_AFTER`, 3 s, or while there is no connection, with why the connection went, that the overseer joins again every 2 s, and when the last word came and at what tick; and Stopped, by the owner or by Windows, or Failed, with the failure's message, once the server said so, with when and the tick of the save it comes back from, until a newer connection's welcome. A failed assertion ends the server at once and says nothing ([ADR-093](ADR-093-a-failed-assertion-ends-the-process.md)), so it reads as No word. Beside the state, the Server button, and Save now and Stop, which ask only of a Running server, and under the state's lines what came of the latest action while the server is Running or Stalled (ADR-104 decision 5). Last, universe time, in days, hours, minutes and seconds, with its tick.
   - **The tiles,** five as wide as each other: the tick's 99th percentile over the last minute of `Health`, at the nearest rank, against its 5 ms budget, with the hour's longest; the ticks of the last second and those dropped in the hour; the last save the log tells of, how long ago in universe time, its tick, its size and how long encoding it took; the bytes out a second to the seats connected, over the last two `Health`; and the process's working set, its share of a core and the disk free under the universe's folder.
   - **The map,** at the left of the row over the seat table: the universe's one system as the game's minimap draws it, sharing its drawing (`Hud::DrawMinimap`, [ADR-100](ADR-100-the-canvas.md) decision 7), with the sectors by their holders, suppressed and cut off, and the ships, structures, Ore and derelicts, every seat in the color the seat table marks it with, and without the camera's view. It draws the view the server sends, full sight or the picked seat's own snapshot, and its heading says which the view shows, so that a pick reads as full sight until the seat's sight comes. No fog is drawn over a seat's sight, whose snapshot holds only what the seat sees, and what it only remembers is drawn as the game draws it. Its All cell, lit while no seat is picked, gives full sight back (owner, 2026-10-27).
   - **What needs attention** (`AttentionOf`), beside the map over the seat table, from the newest `Health`, the last minute of them and the log, the thresholds in `OverseerAttention.h` and nowhere else. What the owner can act on now comes first, each a chip ([ADR-085](ADR-085-one-meaning-per-color.md) decision 1): a game of another build refused within the hour, since its player needs this build; less than 5 GB free on the disk under the universe's folder; and the last save older than two of its intervals, the welcome's `saveSeconds`. Then what to know, in plain text, naming its seat where it has one: a seat's backlog grown over the last 30 s without once shrinking, its round trip over 250 ms at the 95th percentile of the last minute, and its loss over 2% of the packets it sent in that minute; a tick over the 5 ms budget in the last minute; a seat that has waited over 10 minutes for its start to be clear ([ADR-084](ADR-084-universe-without-an-end.md) decision 4); a deputy that has played a seat for over a day ([ADR-079](ADR-079-seat-controller-and-deputy.md)); and every battle under way. Last, dimmed, each check that passes, so that with nothing to act on or know the panel says All well and why.
   - **The seat table,** the canvas's table: a row a seat, marked in its color, its set's in `Models.json` where it has one and otherwise `OVERSEER_SEAT_PALETTE`'s (owner, 2026-10-28), which is never the warning's ([ADR-085](ADR-085-one-meaning-per-color.md) decision 1); and as its columns the seat and who plays it, its status, its connection's round trip with its loss and backlog, its commands over the last minute and those refused, its Ore and income, its fleet against its cap, its nodes and its topics researched. A row of cells filters it: every seat, the players', the AI empires', those whose player is away, or those that what needs attention names, to act on or to know. A press on a heading sorts by it, a second press the other way, the seat breaking a tie. A press on a row picks it and the overseer watches its sight (`WatchSightMessage`); a press on the picked row gives full sight back.
   - **Who played, the last day,** at the right over the log: a lane a player's seat over the day of universe time that ends at the newest tick the overseer was told of, drawn from the day's `seat`, `start` and `battle` records (decision 6), solid in the seat's color while its player played it and hatched while its deputy did, and each recovery a mark across every lane; a seat the records say nothing of is drawn the whole day in the play its `Health` gives it now. Below them a lane of battles, each a mark at its start, filled when a player was present and hollow when only deputies and AI empires fought. AI empires' seats have no lane, since the AI plays them all day.
   - **The universe log:** its records the newest first, the last `RECORDS_SHOWN`, 400, that its filter keeps, every record, the seats', the saves', the battles' or the server's own, each wrapped to the log's width and scrolled back through.
   - **Its windows** (`OverseerWindow`) stand over the overview, each on a canvas of its own laid out after the overview and the map, on a `WindowStack` of the overseer's own, as the game's do ([ADR-100](ADR-100-the-canvas.md)): dragged by their title bars and kept on the screen, closed by their close boxes, and brought to the front by a press in them. The server window opens from the header's Server button, the seat window shows the seat last opened (owner, 2026-10-28), and the confirm window, in the middle of the screen, shows the action last asked to be confirmed (ADR-104 decision 5).
   - **The server window:** the tick split by part over the hour of `Health` held, each part's share and its time a tick, the longest first; the longest tick of each minute of that hour, a bar each, the newest at the right, against a line at the 5 ms budget; the day's long ticks from the day's `tick` records, the longest first, each with when, how many of its minute's ticks took as long and the parts that took most of it, and the ticks dropped in the day from its `dropped` records; the saves the log's records hold, the newest first, each with its size, encoding and write; the game's listener's connections and its joins by outcome since the server started; and the process. Its charts are bars filled on the canvas, as who played's lanes are, so the canvas has no chart widget.
   - **The seat window** opens from the Seat button of the picked seat's action bar, which stands at the seat table's foot, since the canvas's table has no room between its rows, and holds for a player's seat Drop link, while its link is online, and New token (ADR-104 decision 5). The window tells who plays the seat and how it stands; its link over the last four hours, each hour's round trip at the median and the 95th percentile, loss, largest backlog and bytes sent from its `hour` records, the last hour heard a minute a bar at the 95th percentile against the 250 ms of what needs attention, and how long the link was down, from each `join` gone to the next welcomed; its joins of the day, what came of each and the address it came from; its hours of the day; and what waits for its player, the report its `Health` carries while its deputy plays it (ADR-101 decision 5), and its scheduled orders, from its own view, which picking it watches.

## Consequences

- **A third executable** builds with the solution, for x64 and ARM64, Debug and Release. CI builds it with the solution and does not run it: the owner's run against a running universe is what accepts it (AGENTS.md §3).
- **`Neuron::Window` has two settings more,** whose defaults are the game's, so the game's window does not change.
- **`Hud::Theme` makes the game's look reachable** outside `Hud.cpp`, which builds its own windows with it as before, and **`Hud::DrawMinimap` the minimap's drawing,** which the HUD's own minimap goes on drawing as it did.
- **The overseer holds an hour of `Health` in memory,** which grows with a universe's seats; what it takes is not yet measured.
- **Tests.** `OverseerModelTests`: the welcome, an hour of `Health` kept and no more, the log's records and their limit, the day's records and none taken twice, views put together whole and as changes, the closing, the latest action's result, a connection gone and the next one's welcome, and what the server never sends refused. `OverseerClientTests`, over a real connection to a listener that plays the server: the hello with the token, the sight, a view held, the server's reason for closing, and the next connection after `REJOIN_INTERVAL`; QUIC runs in CI's Windows run only. `OverseerAttentionTests`: every check passing when all is well, what to act on and that it comes first, a link wearing down, and long ticks, waits, deputies and battles. `OverseerScreenTests`: each region from a scripted model, the header's Running, its Stalled, its No word after 3 s and why, and its Stopped and Failed, a filter, a sort both ways, a pick and full sight again, the seats' colors, the log's filters, the map in full sight and in a seat's and its All cell, the server window opened by the header's button, dragged and closed, and each of its sections, the seat window opened from the action bar, for a seat online and for one away, what needs attention and the seats that need a look, who played, and the layout and contrast guards at 1920×1080 and 1280×720, which `LayoutGuards.h` holds for `HudTests` too.

## What this forecloses

- **An overseer packaged as the game is,** which a server VM would have to register.
- **An overseer on a software adapter.** On a machine without a GPU it does not start.
- **The overseer in the game or the server.** Each is an executable of its own, and only `GameApp`'s code is shared.
- **A web page or an HTTP server,** without reopening [ADR-001](ADR-001-win32-shell.md) and R14.
