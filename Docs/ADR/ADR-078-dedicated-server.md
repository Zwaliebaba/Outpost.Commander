# ADR-078 — A universe runs on a dedicated server, whose seats are taken with a token at any time, and whose certificate is kept

Status: **accepted** · 2026-10-08
Owns: dedicated-server, universe-settings, universe-seats, universe-certificate, join-file, join-at-launch, lost-connection-menu, leave-window, server-listen-address

## Context

A universe runs on a dedicated server that a player on another machine reaches. It runs on the owner's PC or on a Windows Server VM, and a player's game finds it by its address, its certificate's hash and a seat token (owner, 2026-10-08). A match's server runs inside the game, listens on the loopback and makes a certificate for each match ([ADR-060](ADR-060-quic-in-process.md)). A universe needs more:

- an executable that runs a universe from its folder, with no window, until it is told to stop;
- an address and a port that another machine can reach;
- a certificate that stays the same from one run to the next, so that a player pins it once;
- a seat that only its player can take, at any time while the universe runs, and again after a dropped connection;
- a way for the player's game to learn all of that, and to say why it lost its connection.

## Decision

1. **`OutpostServer` is a console executable** (`SubSystem` Console, not packaged), with ADR-002's row: it includes and links `NeuronCore`, `NeuronServer`, `GameProtocol`, `GameLogic` and `Opponent`, whose AI empires and deputies it hands the server to host ([ADR-079](ADR-079-seat-controller-and-deputy.md)). It reads `Assets\Tuning.json`, `Assets\Map.json`, `Assets\Matchups.json` and the AI's settings files beside itself, copied there by its project, as the game reads its own (ADR-008), and finds `msquic.dll` beside itself through `NeuronCore`'s content (R14).
   - `OutpostServer --new-universe <folder> [--host <name>] [--address <ip>] [--port <n>] [--seed <n>] [--ai <player>[:<difficulty>]] [--overseer-address <ip>] [--overseer-port <n>]` writes a new universe's settings and refuses a folder that holds a universe already. An option it is not given leaves decision 2's default, and the seed's is the system clock's count since its epoch as the universe is made. `--ai` gives a seat to an AI empire, Normal unless it names Easy or Hard (ADR-079).
   - `OutpostServer <folder>` runs the universe, hosting an AI empire for each AI seat and a deputy for each player's (ADR-079). Before it starts the server it makes the overseer's link and writes `Overseer.json` in the folder ([ADR-101](ADR-101-the-overseers-channel.md)). Ctrl+C, Ctrl+Break, closing the console, signing out and shutting down all ask it to stop; `ServerConsole` says whether Windows asked, signing out or shutting down, or the owner. It then tells the overseer how it ends and destroys the server, so that the universe's folder writes its last save (ADR-077). The console handler waits up to 5 seconds for that, since Windows ends the process once the handler of a close returns. Once a second the main thread reports to the overseer (`InProcessServer::Report`), which takes the server's tick timings, which is where a failure on its thread reaches it (ADR-025); a failure is told to the overseer and then ends the process with its message on standard error.
   - `OutpostServer` with no arguments runs the default universe, in `Outpost Commander\Universe` in the owner's documents (`SHGetKnownFolderPath(FOLDERID_Documents)`), beside the game's join file (decision 9), making it first as `--new-universe` with no options would when the folder holds no `Universe.json` (owner, 2026-10-26).
   - `--universe-run` is [ADR-082](ADR-082-universe-log-and-universe-run.md) decision 4's, and `--matchups` [ADR-083](ADR-083-battle-matchups.md) decision 5's.
2. **A universe's settings are `Universe.json` in its folder** (`UniverseSettings`): the address the server listens on, `*` by default, so that a player naming `localhost`, which resolves to IPv6 first, reaches it as well as one reaching it on IPv4 (decision 6); its UDP port, `DEFAULT_UNIVERSE_PORT` (45000) by default; the address and port it listens for its overseer on, `overseerAddress` and `overseerPort`, `127.0.0.1` and 45001 by default, which settings made before them read as (ADR-101); the host its players reach it at, which the join files name, `localhost` by default; the seed, as a string of its decimal digits, since a JSON number cannot hold every 64-bit seed; and a seat for each of the map's starts, each a player's with a token, or an AI empire's with its difficulty (ADR-079). The owner makes them once; the server only reads them. A universe whose folder holds a save comes back with the save's seed (ADR-077).
3. **A seat is taken with a token.** A `SeatToken` is 128 bits from `std::random_device`, which draws from the system's cryptographic source under MSVC and Linux, never from the simulation's PRNG (ADR-009). The hello carries it after the player. `Server::OpenSeat` takes the seat's token, and the `ServerAddress` it returns carries it; the shell gives each match's seat a new one. A hello whose token is not its seat's is refused as `SeatRefused`.
4. **A universe's seat is taken at any time, and the newest connection holds it.** A match's seats are taken before it starts, and `Start` throws while one is open. A universe, a server made with `ServerDesc::universe`, starts with its seats open, and takes a hello with the seat's token at any time. A hello for a seat that is held replaces the connection that held it, which is closed with `CloseReason::SeatTaken`. The newest connection wins so that a player whose connection dropped without the server knowing yet takes its seat back at once, rather than waiting out MsQuic's idle timeout. The swap is made under the seat lock, and the old connection is closed after the lock is let go, since its own callbacks take it. A command from a connection the seat was taken from is dropped. A snapshot is whole, so the first after a seat is taken shows everything the player sees and remembers; the shots and destructions of the ticks it missed are lost, which is presentation.
5. *(retired)*
6. **The listener listens on the address it is given** (`QuicListener::Desc::address`, from `ServerDesc::quicAddress`), as an IPv4 or IPv6 literal, on every address of both when it is given `*` (`QuicListener::EVERY_ADDRESS`), and on `127.0.0.1` when it is given none. MsQuic matches a connection only to a listener of its own address family, or of none, so a listener on `0.0.0.0` refuses a client that reaches it on IPv6, and the client reads that as a failed application-protocol negotiation (`0x80410007`), which `QuicChannel` names as a listener it did not find. It listens on `ServerDesc::quicPort`, or a port the system chooses at zero. An address that is not one is refused. `OpenSeat` names the host a player on the same machine reaches it at: `127.0.0.1` for a server given no address or listening on IPv4's every interface (`0.0.0.0`) or on both families' (`*`), `::1` for one listening on IPv6's (`::`), and otherwise the address it listens on.
7. **A universe's certificate is kept in its folder** (`QuicListener::Desc::identity`, from `ServerDesc::universe`). `ServerCertificate` made with a folder:
   - opens the certificate in `Certificate.der` and the key whose name `Certificate.key` holds, and uses them when the key is in the user's key store and the certificate is valid now, after naming the key on the certificate (`CERT_KEY_PROV_INFO_PROP_ID`), as `CertCreateSelfSignCertificate` does, so that Schannel finds it;
   - otherwise makes a new key and certificate, valid for five years, writes both files, and deletes the key of a certificate that is not valid now;
   - leaves the key in the store when it goes.

   So a player pins a universe's certificate once: its hash changes only when its key is lost or after five years. A match's certificate is made and deleted as [ADR-060](ADR-060-quic-in-process.md) decision 6 has it.
8. **A join file tells a player's game where its seat is** (`JoinTicket`): a JSON object of the host, the port, the certificate's SHA-256 and the seat's token in hexadecimal, and the player. `OutpostServer` writes `Join-Player<n>.json` for each player's seat into the universe's folder each time it runs, and the owner hands each to its player.
9. **The game joins a universe** from `--join <file>`, or from the menu's "Join universe", which shows when the player has `Outpost Commander\Join.json` in their documents (`SHGetKnownFolderPath(FOLDERID_Documents)`). The documents, not the game's local folder, because the packaged game's own application data is redirected away from where a player would put a file, and the documents are not. **With that file there, the game joins at launch** (owner, 2026-10-25): once, as the window shows, before it offers a skirmish, unless `--join` names another file or `--measure`, `--load`, `--stress` or `--matchup` is given. The join at launch gives the handshake 3 s (`LAUNCH_JOIN_CONNECT_TIMEOUT`, as `QuicTransport`'s connect timeout), so that a player whose server is not there waits no longer than that for the skirmishes; `--join` and the menu's Join universe give it `QuicChannel::CONNECT_TIMEOUT`, 10 s. Nothing joins again of its own accord: after a join that fails, or a return to the menu, only the menu's Join universe does. A joined universe is the player's connection alone: no server, rival or AI in the game. **The join does not hold up the frame loop** (owner, 2026-10-25): the shell makes the connection on a thread of its own (`std::async`), and the frame loop takes it once the server has welcomed the player or the join has failed, at most `WELCOME_TIMEOUT` later. Until then the menu says "Connecting to" and the server, as `Hud::ServerName` writes it ([ADR-086](ADR-086-where-the-match-runs.md) decision 1), and only Quit can be pressed. A join that fails goes back to the menu with its notice. The window stays hidden while the game loads, as [ADR-049](ADR-049-startup-in-parallel.md) has it: a join is the one wait the player sees. Quitting while a join connects waits for it to end.
10. **A universe's lost connection is joined again, and any other lost connection takes the player back to the menu, saying why.** `QuicChannel::PeerErrorCode` gives the code the peer closed with, and `QuicTransport` throws `ServerClosed` with `DescribeClose`'s words for a `CloseReason`.
    - **A universe's connection lost but for the server's own close** as `Finished`, `WrongVersion`, `SeatRefused` or `SeatTaken` (`MayJoinAgain`), or that has brought no snapshot for 10 s, is joined again with its join file's ticket, at once and then every 2 s, each join given 2 s to connect, while the match stays on the screen and the tag says "Reconnecting · 5 s" ([ADR-086](ADR-086-where-the-match-runs.md) decision 2) (owner, 2026-10-26). The joins run on threads of their own, as a join from the menu does (decision 9), and an order given meanwhile goes nowhere.
    - **A join the server refuses, or 30 s without one that takes, ends it.** 30 s is half the deputy's minute ([ADR-079](ADR-079-seat-controller-and-deputy.md) decision 4), so a link that drops for a moment never hands the seat to the deputy.
    - **The shell shows the menu with the reason in the warning's color** (`Hud::MenuState`) for a skirmish's lost connection, for a universe's the server closed, and for one not joined again in time.
11. **A universe is left from the leave window** (owner, 2026-10-25). In a universe, Esc with no window open and nothing armed for the controls to cancel (`PlayerControls::IsArmed`) opens the leave window (`WindowKind::Leave`, [ADR-031](ADR-031-floating-windows.md) decision 5), at first in the middle of the screen: "Leave for the menu?", that the deputy keeps the empire going, and two buttons side by side. Leave universe is the banner's Back to menu: the shell ends the connection and shows the menu with no notice, and the next skirmish's server is made. The server sees the connection gone at once, and the deputy takes the seat 60 s of ticks later ([ADR-079](ADR-079-seat-controller-and-deputy.md) decision 4). Stay closes the window, as its × and Esc do. The universe runs on behind the window. A skirmish has no leave window: its way back stays the banner's ([ADR-020](ADR-020-ai-and-match-flow.md) decision 9).

## Consequences

- **Tests.**
  - `UniverseSettingsTests`: settings and join files read back as written, every refusal, a seed past 2⁵³ intact, and the overseer's address and port read as their defaults from settings made before them.
  - `QuicTransportTests.TakesItsSeatAgainAfterItsLinkWent`: a client whose link has carried nothing for 10 s joins again and takes its seat back, the connection it took it from is closed with `SeatTaken`, and which closes `MayJoinAgain` allows. The shell's joins need Windows; CI builds them.
  - `QuicTransportTests`: a seat refused without its token, a universe's seat taken after it starts and again by a newer connection, a universe's certificate kept and used by Schannel when it runs again, a listen address, a hello of another version, and a join that gives up in the time it is given (`GivesUpAJoinInTheTimeItIsGiven`).
  - `HudTests.OffersAUniverseAndSaysWhyTheLastGameEnded`: the menu offers a universe to join and says why the last game ended.
  - `HudTests.OffersToLeaveAUniverse`: the leave window in the middle, its words whole, Leave universe and then Stay; `PlayerControlsTests.SaysWhetherAnythingWaitsForAClick`: an attack-move, a standing order and a placement each keep Esc from it until Esc cancels them. `GameClient`'s Esc needs D3D12 and Windows, so it has no test; CI builds it.
- **The dedicated server needs Windows 11, or Windows Server 2022 or later.** It listens over QUIC, which needs TLS 1.3 from Schannel ([ADR-004](ADR-004-quic-transport.md)).
- **A universe's port is reached through the owner's router and firewall.** Windows Defender Firewall asks about `OutpostServer` the first time it listens on an interface other than the loopback. A server behind a router needs the port forwarded. Neither is the game's to do.
- **The tokens are in `Universe.json` and the join files as plain text.** Anyone who reads the universe's folder or a player's join file can take that seat. That is the trust of a circle of friends, not of a public server.

## What this forecloses

- **Taking a seat without its token,** or a player id alone.
- **A second connection holding a seat beside the first.** The newest one holds it.
- **Validating a universe's certificate against a root.** It is pinned ([ADR-060](ADR-060-quic-in-process.md) decision 6), and kept.
