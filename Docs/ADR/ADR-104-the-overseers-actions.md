# ADR-104 — The overseer asks the server for actions on its channel, which the server's thread carries out between two ticks

Status: **accepted** · 2026-10-28
Owns: overseer-actions

## Context

The overseer watches a universe over a channel of its own ([ADR-101](ADR-101-the-overseers-channel.md)) and acts on the server but never on the simulation (owner, 2026-10-27). [The overseer's proposal](../Plans/UniverseOverseer.md) names its actions: Save now, Stop, Drop link and New token. The owner decided that each is written to the universe log, and that Stop asks to be confirmed in a window where Save now does not (owner, 2026-10-28). The owner also decided that Drop link closes the seat's connection with a reason the game does not join again after, its deputy taking the seat at once or after its minute as the owner picks, and that New token makes the token afresh, writes it into the universe's files and drops whoever joined with the old one (owner, 2026-10-28). This ADR records how an action crosses, how the server carries out each, and how the overseer asks for them.

## Decision

1. **An action crosses as one message of the overseer's own, and its answer as another** (`OverseerProtocol.h`): `ActionMessage` names the action (`OverseerAction`: `SaveNow`, `Stop`, `DropLink` or `NewToken`), its seat for Drop link and New token, no player for the others, and for Drop link whether the seat's deputy takes it at once; `ActionResultMessage` names the action and its seat, whether the server did it or refused it, and the server's words for it. One message with a kind rather than one an action, since the four share every field but the deputy's choice. They are the overseer's messages, so its layout and hash change and an overseer of another build is refused (ADR-101 decision 4); the game's messages do not change.
   - **The link takes an action from the overseer that holds the channel,** and closes one that names what it may not, a seat for Save now or Stop, or no player's seat for Drop link or New token, with `MalformedMessage` (ADR-101 decision 3). MsQuic's thread keeps it with the address it came from (`OverseerLink::TakeActs`).
   - **The server's thread carries it out at its next tick,** after the simulation's tick and never inside it, as it saves (`InProcessServer::Act`), and answers the overseer that holds the channel then (`OverseerLink::SendResult`). No action reaches the simulation, its state or its command log.
2. **Save now saves the universe at that tick, as the save each minute is** ([ADR-077](ADR-077-universe-state-on-disk.md) decision 7): the server's thread encodes it, the folder's thread writes it, and the answer comes once the folder says it is written, "Saved at tick N, written in X ms.". One asked for while another asked for is still being written, or a second asked for at the same tick, is refused, naming the tick of the one being written. A save due at that tick is the same save.
3. **Stop stops the server as Ctrl+C does.** The server's thread marks it asked (`InProcessServer::StopAsked`) and answers it at once; `OutpostServer`'s main thread, which looks each `CHECK_INTERVAL`, 1 s, closes the server as it does on Ctrl+C, and `Closing` says its owner stopped it (ADR-101 decision 8). The universe comes back from its folder when the server is started again on its machine, from its last save with the commands logged since; nothing on the overseer starts it.
4. **The universe log writes each action** as an `overseer` record, at the tick the server carried it out, with the address it came from, whatever came of it, as it writes the overseer's comings and goings ([ADR-082](ADR-082-universe-log-and-universe-run.md) decision 1): `save`, `stop`, `drop player <p> deputy <now or later>` and `token player <p>`.
5. **The overseer asks for an action only of a running server.** The header's Save now and Stop stand beside its Server button, and the picked seat's action bar holds, for a player's seat, Drop link, while the newest `Health` says its link is online, and New token; each is dimmed and takes no press unless the header says Running, since a Stalled server's thread may never carry one out and none is asked of a server it has no word from ([ADR-103](ADR-103-the-overseer-application.md) decision 7). An AI empire's seat has neither. Save now asks at once. Each of the others opens the confirm window (`OverseerWindow::Confirm`), in the middle of the screen, on the action last asked for, which says what it does: its first button asks for it and closes the window, dimmed as the buttons that opened it are, and its second or its close box closes it asking nothing. Drop link's window holds the deputy's choice, a cell for after `DEPUTY_DELAY_SECONDS` and one for at once, after it unless the owner picks at once.
   - **What came of the latest action is told under the header's state** while the server is Running or Stalled, with how long ago, wrapped, since the server's words may run long, and a refusal in the warning's color as a refused text is ([ADR-085](ADR-085-one-meaning-per-color.md) decision 1). The model keeps it until a newer connection's welcome (`OverseerModel::LatestResult`).

6. **Drop link closes the seat's connection with a close reason of the game's, `DroppedByOwner`** ([ADR-060](ADR-060-quic-in-process.md) decision 5), which the game does not join again after (`MayJoinAgain`, [ADR-078](ADR-078-dedicated-server.md) decision 10): it goes back to its menu saying the server's owner closed the connection and that its player joins again from the menu, with the same join file. The seat's deputy takes it as the owner picked: as soon as the connection is seen gone, or `DEPUTY_DELAY_SECONDS` after the drop, as for any connection gone, unless its player joins again meanwhile (`SeatController::Dropped`, [ADR-079](ADR-079-seat-controller-and-deputy.md) decision 4). The universe log writes the link's end as a `join` record, `gone player <p> dropped`, since the server closed it itself (ADR-082 decision 1). A seat with no link open is refused, as having none to drop.
7. **New token makes the seat's token afresh and drops whoever joined with the old one** (`NewSeatToken`). The server's thread writes it into `Universe.json`, to a file beside it renamed over it once whole, as a save is ([ADR-077](ADR-077-universe-state-on-disk.md)), and then the seat's join file the same way (`WriteSeatToken`, ADR-078 decision 2); only once both are written does the listener take the new token and refuse the old, and then it drops the seat's link as Drop link does, its deputy playing the seat at once. The answer names the join file, which the owner hands the seat's player. A write that fails is refused with why, and the seat keeps its token for as long as the server runs; when `Universe.json` was written and the join file was not, the server takes the new token at its next start, and writes the join file then.

## Consequences

- **An action waits for the server's thread.** A Stalled server carries out none until its tick runs again, and a stuck one is stopped from Windows, as it was before the overseer had actions.
- **An answer goes to the overseer that holds the channel when the server gives it,** which is a newer one than asked when the channel was taken meanwhile.
- **New token writes two small files on the server's thread,** between two ticks: the time is the files' to write, which is not measured, and is of a press the owner makes rarely.
- **Drop link is no ban:** the player joins again from the menu with the same join file. New token is how a seat is taken from whoever holds its join file.
- **A save asked for is a save like any other:** the folder keeps the newest of them ([ADR-077](ADR-077-universe-state-on-disk.md)), so an owner who asks often drops the older saves sooner.
- **Tests.**
  - `OverseerProtocolTests`: an action and its answer cross as they were sent. `UniverseLogTests.WritesTheOverseersActions`: each action's record. `SeatControllerTests.ALinkTheOwnerDroppedHandsTheSeatOverAsPicked`. `UniverseSettingsTests.WritesASeatsTokenBack`: the token in `Universe.json` and the join file, nothing left half written, and the seats it has no token for. `QuicTransportTests`: `DroppedByOwner` among the closes not joined again.
  - `OverseerLinkTests`, over a real connection: Save now answered once written, with its record, and `Closing`'s last save that save; a second save refused while the first is written, from a server stepped by hand; Stop asked, answered and written; Drop link with the deputy at once and after its minute, the game told why, and none to drop; New token written into both files, the old token refused and the new one taken; and an action that names what it may not closed as malformed. QUIC runs in CI's Windows run only.
  - `OverseerModelTests.KeepsTheLatestActionsResult`. `OverseerScreenTests`: Save now and Stop from the header, Stop's window and its two answers, Drop link and New token from the action bar and their windows, the deputy's choice among them, the result under the header, the actions asked of no server that does not run, and the layout guards with Drop link's window open.
