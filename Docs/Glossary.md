# Outpost Commander — Glossary

Status: **living** · The game's nouns, the identifiers that hold them in code and data, and the section of [the living design](OutpostCommander.md) that gives each one's rules

Look a word up in its chapter's table: "In code" names its types, members, constants and data keys, as a grep finds them, and "Section" is the section of the living design that gives its rules. A term's numbers are the [Catalogue](Reference/Catalogue.md)'s, and its keys are the [Controls](Reference/Controls.md)'.

## Overview

| Term | In code | Meaning | Section |
|---|---|---|---|
| Outpost Commander | `Outpost`, `OutpostCommander/OutpostCommander.vcxproj`, `OutpostServer/OutpostServer.vcxproj` | The game: real-time strategy in space on a flat plane, where a player builds a base with Constructors, mines Ore, researches, designs its own ships from components and fights for territory. Outpost is the namespace of every game layer (AGENTS.md R9); the menu's title reads "Outpost Commander". | Game §overview |
| Player | `PlayerId`, `Simulation::PlayerState`, `Snapshot::player`, `Simulation::AddPlayer` | One side of a match or a universe, a person at the client or an AI, with its own Ore, designs, research, ships and structures. | Game §overview |
| Simulation | `Simulation`, `InProcessServer::SimulationState` | The state the server keeps of a match or a universe and advances each tick: every player, ship, structure, sector and order. In prose "the simulation" names it, and "world" means only the space models are placed and drawn in, as in world matrix and world space (owner, 2026-10-25). | Game §overview |
| Tick | `RulesTuning::tickHz`, `Snapshot::tick`, `Simulation::Tick`; in `Tuning.json`: `rules.tickHz` | One step of the simulation, at the fixed rate the tuning data gives; the tick is the game's only clock, and the client interpolates between ticks. | Game §overview |
| Snapshot | `Snapshot`, `Simulation::BuildSnapshot`, `EntityView`, `SnapshotInterpolator` | What one player may see of the simulation after a tick, which the server sends that player and the client draws from; under fog of war it holds only what the player sees and remembers. | Game §overview |

## Session

| Term | In code | Meaning | Section |
|---|---|---|---|
| Match | `Simulation`, `Snapshot::matchOver`, `Simulation::MatchOver`, `MatchEnding` | A game on the map from the starting bases to its end, against the AI in a skirmish; it ends by losing production or by domination, and the simulation runs on after it. | Game §session |
| Skirmish | `ActionKind::StartSkirmish`, `Hud::LayMenu`, `InProcessServer` | A match against the AI started from the menu at a chosen difficulty, with its server inside the game on a thread of its own; the connection panel reads "Local skirmish". | Game §session.skirmish |

| Losing production | `MatchEnding::LostProduction`, `Simulation::DecideMatch`, `Simulation::EndMatch` | A player with neither a Command Station nor a finished Shipyard has lost; a Shipyard under construction keeps no one alive. | Game §session.end |

| Dedicated server | `OutpostServer/OutpostServer.vcxproj`, `ServerConsole`, `--new-universe`, `--address`, `--port` | The console program that runs a universe from its folder, with its AI empires and its players' deputies on its own thread, and that the game joins over QUIC. | Game §session.server |
| Join universe | `ActionKind::JoinUniverse`, `JoinTicket`, `--join`, `MenuState::joinUniverse`, `LAUNCH_JOIN_CONNECT_TIMEOUT` | Joining a universe on a dedicated server: at launch, once, when the player's documents hold a join file, then from the menu, or with --join; the join file gives the address, port, certificate hash, player and seat token. | Game §session.join |
| Leave universe | `WindowKind::Leave`, `ActionKind::Stay`, `PlayerControls::IsArmed` | Going back to the menu from a universe at any time: Esc, with no window open and nothing armed, opens the leave window, whose Leave universe ends the connection and whose Stay closes it; the deputy takes the seat a minute later. | Game §interface.windows.leave |
| Overseer | `OverseerLink`, `OverseerProtocol.h`, `OverseerTicket`, `Overseer.json`, `--overseer-address`, `--overseer-port` | The dedicated server's management console, an application with a channel of its own to the server: it sees the universe in full sight, how the server and each seat's link are, and the universe log as it is written, and changes nothing in the universe. | Server | `Server`, `InProcessServer`, `QuicTransport`, `LoopbackTransport` | The authoritative program that runs the simulation, applies the players' commands and sends each its snapshot, over QUIC; in a skirmish it runs inside the game. | Game §session |
| Match log | `MatchLog`, `Tools/MatchLog.py`, `--log` | The client's record of a match, such as each side's warships, the first shot, engagements, salvage and upgrades, which Tools/MatchLog.py summarizes. | Game §session.instruments |
| AI-against-AI matches | `--ai-matches`, `AiMatchesOptions`, `AiMatchesDesc`, `--matches`, `--first-seed`, `--limit-minutes` | Seeded matches between two AIs on the real server without a window, run for measurement and scored by Tools/MatchLog.py --ai-matches. | Game §session.instruments |
| Measurement runs | `--measure`, `--stress`, `--load`, `StressLoad`, `PlaceMeasurementLoad`, `LoadDriver`, `Tools/FrameTimes.py` | Runs of the game that log frame, tick and order-response times: --stress keeps two large fleets fighting and --load keeps them moving; Tools/FrameTimes.py summarizes the log. | Game §session.instruments |
| Engagement | `MatchLog::SectorFire`, `ENGAGEMENT_WINDOW_SECONDS` | In the match log, ships of both sides firing in one sector within a short window of each other. | Game §session.instruments |

| Center sector | in `Map.json`: `sectorKinds[].name` "center" | The middle sector, its own mirror, with contested-yield asteroids and a pirate stronghold. | Game §map.kinds |
| Rich sector | in `Map.json`: `sectorKinds[].name` "rich" | One of the two empty corners, equally far from both starts, with rich-yield asteroids and a pirate stronghold. | Game §map.kinds |
| Ore asteroid | `EntityKind::Asteroid`, `OreAsteroidPlacement`, `OreRule`; in `Map.json`: `oreAsteroids`, `sectorKinds[].ore[].count`, `sectorKinds[].ore[].radiusMeters`, `oreAsteroids[].radiusMeters` | A mineable rock that blocks movement as a circle and holds one Mining Rig; the homes' are fixed and the rest are placed from the seed. | Game §map.asteroids |
| Asteroid field | `EntityKind::AsteroidField`, `AsteroidFieldPlacement`, `FieldLayout`, `FieldRock`; in `Map.json`: `asteroidFields` | A non-mineable cluster of rocks, a circular obstacle that bounds the sectors and makes their passages and chokepoints. | Game §map.fields |
| Minimum gap | `Map::minimumGapMeters`; in `Map.json`: `minimumGapMeters` | The narrowest passage the map allows between obstacles, the edge and the starts, which keeps every part of the map reachable from both starts. | Game §map.fields |
| Placement from the seed | `PlaceContent`, `PlacementRules`; in `Map.json`: `placement`, `placement.borderMeters`, `placement.nodeClearanceMeters`, `placement.oreSpacingMeters` | At a match's setup the seed places every ore asteroid but the homes', the pirate outposts and the derelicts, one half of the map mirrored through its center so both seats get the same map. | Game §map.placement |
| Seed | `Simulation::Simulation`, `PlaceContent`, `--seed`, `Neuron::Random` | The number a match is set up from: it places the map's content and drives the simulation's random draws, so the same seed and commands replay on the same build. | Game §map.placement |
