How a design's stats are derived

A design is a hull, a drive and a weapon, with a module or none. Its stats are derived from those, never stored in the data (ADR-014 §Decision 1). The server and the designer call the same function, DesignStatsOf, on component views that the server sends with the player's research already applied (ADR-017 §Decision 5; DesignStats.h:75-95; ShipDesign.cpp:38-84).

A design's full name "Hull+Drive+Weapon", then "+Module" when it has one, e.g. "Small+Ion+Mass Driver+Sensor Array". The designer uses the module's initials where the whole name would pass 32 characters. ShipDesign.cpp:132-140; Designer.cpp:122-150; ADR-058 §Decision 6
A module on a starting design's components Takes the design's name and the module's initials, "Lancer+SA" Designer.cpp:134-145; ADR-069 §Decision 5
Abbreviation The capital initial of each word: hulls S, M, L; drives I, F, P; weapons MD, L, MR, FB, RC; module SA. A design's code is the initials joined by "·", e.g. "S·I·MD·SA". DesignStats.h:23-37; Hud.cpp:420-432; Phase 1 §5 "What the designer shows for each"
Name rule 1–32 printable ASCII characters, not all spaces Command.h:68-84; ADR-017 §Decision 6
A saved design's components Never change. Other components are a new design, and a rename keeps its components. ADR-017 §Decision 6
Queue on unsaved picks Saves the design first, and the queue follows once the server has it. A save not back within 40 ticks (2 s) is dropped. Designer.h:112-121; ADR-023 §Decision 1-4
A design's retreat Never, Half (50%) or Quarter (25%); Quarter by default. Every ship built to the design starts with it. RetreatThreshold.h:7-30; ADR-075 §Decision 4
Pirates' designs Base-level stats, with no research. Any component will do, since nothing unlocks a pirate's design. Tuning.h:257-258; Tuning.json: pirates l.119-129
Matchup designs A starting design where one matches, otherwise saved as "Matchup design N". A matchup's ships never retreat. Simulation.cpp:769-782; ADR-083 §Decision 2
